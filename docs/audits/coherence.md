## What's already coherent

- **Drive isolation is genuinely one-way and separate-process** — the sharpest boundary in the system holds in both directions (see Std-4/6 above). This is safe to build on. The only blemish is documentation (a dead file's stale docstring), not behavior.
- **`CycleGuardService` (969 lines) and `ConfidenceUpdaterService.update()` are models of cohesion, not god-objects.** The graph's `god-function` flags on `enqueue`/`drainNext` (hubScore 9/7) and `update` (hubScore 7) are FALSE POSITIVES — hubScore measures fan-in, not internal sprawl. `CycleGuardService` has one responsibility (decision-cycle concurrency: queue/mutex/watchdog/breaker/epoch), is exhaustively documented against its spec, and surfaces as a hub only because many sites call it. `ConfidenceUpdaterService.update()` is a 12-line dispatcher delegating to three private path methods with all math kept in the shared `computeConfidence()` per Std-6. **These are the reference cohesion bar the two P1 god-objects should be refactored TOWARD** — focused service, spec-traceable, CANON concerns isolated and labeled.
- **Error handling is more coherent than typical.** There is NO throw-vs-Result idiom split to fix — a repo-wide search for `Result<,Error>`/`Either<>` returns essentially nothing; the codebase uniformly uses throw-or-typed-degraded-return. The dominant pattern is consistent: try → `logger.error/warn` (often paired with `vlog`) → return a typed degraded value (`{ ok: false }`, `[]`, `null` with a documented null-contract). Boundary exception-isolation is deliberate and commented (e.g. `decision-making.service.ts:431-453` isolates MoodBleedMonitor failures so a monitor can never break a cognitive cycle). Failure auditing is first-class: the learning pipeline writes a dead-letter row (`update-wkg.service.ts` `writeDeadLetter`) so silent data loss becomes auditable. **This dead-letter + dual-trace pattern is the documented house style the logging-convention ADR (P1) should codify** — remediation should extend it, never introduce a new error-handling abstraction.
- **Controller→service→storage layering is clean everywhere except the one metrics outlier.** Seven of eight controllers (drives, graph, rules, voice, supervisor, skills, llm) inject zero storage clients and go through services; `metrics.controller.ts` is the single boundary inversion (P1). The pattern to bring it back to already exists in its siblings.
- **The EP7 seam-extraction pattern (CycleGuard/TickEngine/SensoryPredictionRouter/TensorCandidateBuilder/RecallRetrievalHelper) is proven** — the decision-making god-object P1 is finishing a decomposition the team already started well, not inventing a new approach.
- **Justified divergences are real, not accidental** — the drive child-process `console.*` logging and the `.core.ts` decorator-free modules are both correct responses to genuine constraints (process isolation; esbuild/tsx parameter-decorator limitation). They need documentation, not "fixing."
